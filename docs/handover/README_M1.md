# M1 — Data Set Used & Data Description

The project uses the supplied `cars.xlsx`, containing 762,091 U.S. used-car listings and 20 source fields. The project identifies the source as Cars.com listings collected in April 2023 and published by Andrei Novikov on Kaggle. The upload is an Excel copy rather than the `cars.csv` referenced in the task instructions. The full workbook was scanned to extract 16,192 records labelled Electric. The exact source file checksum and extraction counts are recorded in `data/raw/source_profile.json`.

The source includes manufacturer, original model/trim, model year, mileage, engine, transmission, drivetrain, colours, recorded vehicle history, seller information, driver ratings, price reductions and asking price. Mileage is treated as miles and price as U.S. dollars according to the project specification. The outcome is asking price rather than a completed transaction price. There is no original new-car price or battery-health measurement, so the analysis does not directly estimate a resale-retention percentage.

The agreed model-name exclusions remove 962 plug-in hybrid, range-extender or hydrogen-labelled listings. Removing 75 exact duplicates leaves 15,155 records, covering 19 brands and 44 explicitly defined M1 model families. Each retained listing receives a stable zero-based `listing_id`; the source Excel row is retained separately. The full original model description remains available alongside the canonical model family. Generic labels for 33 records are flagged for model-name review, and eight records require additional BEV-status confirmation: four have missing/zero engine descriptions and generic model names; four BMW i3 listings describe a 0.65L engine, consistent with a possible range extender. BMW’s official technical information identifies the optional range extender as a 647cc petrol engine; this supports a review flag, but does not verify these individual listings (https://www.press.bmwgroup.com/usa/article/detail/T0143611EN_US/the-bmw-i3). They remain in the handover pending team review. The 44 model families must not be reported as 44 successfully complaint-matched models; M2 must establish that coverage independently.

# M1 — Data Understanding & Data Processing (Listings)

**Cohort and category cleaning.** Exact duplicates are detected over all original fields before new identifiers are assigned. The provenance row number is excluded from duplicate detection. `fuel_type` is removed after cohort selection; `mpg` is removed because it is entirely missing in the retained EV cohort. Drivetrain abbreviations and capitalisation are standardised, while unknown drivetrain values remain missing. Model families are mapped explicitly so that Bolt EV/Bolt EUV, IONIQ EV/IONIQ 5, Tesla Model 3/S/X/Y and other multi-word model names are not collapsed by a first-token shortcut. Raw trim names are retained for traceability.

**Feature engineering.** Approximate age is calculated as 2023 minus model year. Annualised mileage is mileage divided by `max(age,0.5)`; this is a proxy, particularly for model-year-2023 vehicles, rather than measured annual driving. A high-mileage flag identifies values above 15,000 annualised miles, and a premium-brand indicator follows the project's stated brand list. Missing mileage produces missing derived mileage features rather than a false low-mileage classification. The log target is the natural logarithm of positive asking price. Recorded price reductions are zero-filled under the project assumption; `price_drop_raw` and `price_drop_was_missing` preserve the original observation. `initial_price = price + price_drop` is a reconstructed listing reference, not MSRP. The `price_cut_flag` indicates an observed positive recorded reduction, not whether a future reduction will occur.

**Missing data.** Seller rating is missing for 23.35% of retained listings, driver rating for 10.76%, accident history for 5.35%, one-owner history for 6.43%, personal-use history for 5.36%, and mileage for 0.04%. Missingness is profiled by field, manufacturer and seller, and driver-rating gaps are compared with review counts. MAR/MNAR explanations are hypotheses; these observational data do not prove a missingness mechanism, and seller size is not observed. Unknown accident history is not treated as no accident.

**Imputation comparison.** A reproducible 80/20 split reserves 3,031 held-out test IDs and uses 12,124 development listings for a shuffled five-fold comparison. Both methods use the same Ridge model (alpha=1) and folds, with four continuous fields (age, mileage, seller rating, driver rating) and three binary history fields. Continuous features are scaled using the training fold before numeric imputation. Median and five-neighbour KNN are compared for continuous fields; binary histories use most-frequent imputation in both pipelines to avoid fractional accident/owner labels. The project-designated error is removed only from each fitting subset, never from a validation fold or the held-out test. The held-out test is not scored during method selection.

Using the same Ridge pilot and five-fold cross-validation on the development set only (12,124 listings), median imputation achieved a mean log-price MAE of 0.363340, versus 0.363372 for KNN. Median imputation is selected because it has the lower primary score and is simpler; the difference is negligible and does not establish statistical superiority. Binary history fields use most-frequent imputation in both methods. Missing values remain in the clean CSV, and preprocessing must be fitted inside each training fold. Groupwise IQR is the primary explainable outlier review screen, with Isolation Forest as a complementary check; neither is an accuracy winner without verified error labels. Only the project-designated Toyota bZ4X record (listing_id 13975, USD333,333) is listed for training-only exclusion. All statistical outliers and the held-out test records remain in the handover.

**Outlier review.** Log-price IQR bounds are estimated within model family × model year. A group with fewer than ten cars uses the entire model-family distribution, including its larger-year groups. IQR flags 248 records. Isolation Forest uses log price, mileage and age, with missing input mileage filled by the descriptive cohort median, contamination=0.01 and random_state=42; it flags 152 records. The methods agree on 16 flags. These figures are descriptive full-cohort diagnostics, not learned predictive features or evidence that every flagged listing is erroneous. Near-new vehicles, high-priced premium cars and possible collector models remain. The Toyota bZ4X USD333,333 observation is designated as an error by the project instructions, not independently validated from an original live listing. It remains in the clean data and is isolated in `outlier_ids.csv` for training-only exclusion. No statistical flags trigger automatic row deletion.

**Exploration and limitations.** Seven requested charts/tables are produced, each with a plain-English takeaway. They describe an April 2023 cross-section. Median price by age cannot establish a within-vehicle annual depreciation rate; accident boxplots do not control all differences in trim, mileage, age and damage severity; and brand median prices are not brand retention rankings. The all-cohort EDA includes held-out rows for descriptive reporting, so it must not be described as a completely unseen/blind test. No held-out predictive score is used to choose the imputation method. These price-based diagnostic flags must be excluded from model inputs. M5 must refit any operational outlier detector only within fitting data if an additional training rule is introduced.

Source reference: https://www.kaggle.com/datasets/andreinovikov/used-cars-dataset . The page did not expose a retrievable field dictionary during this run; absence of `price_drop` meaning no previous cut and its relationship to the first asking price remain project assumptions. The uploaded file is the source of all reported counts and values.


### Additional condition features (teacher feedback, 15 October)

We added seven transparent condition features: a low-mileage-for-age flag, a near-new flag, a clean-history flag, an equal-weight condition score, age and mileage bands, and a cumulative-use battery-wear proxy. Low mileage means annualised mileage below 7,500 miles, using a minimum age denominator of 0.5 years. Near-new means approximate age no greater than one year and mileage below 5,000 miles. Clean history means an explicit record of no accident or damage; missing history remains unknown. The condition score sums the three flags (0–3) and remains missing if any component is unknown. These definitions and cutoffs are project assumptions, not verified mechanical standards.

Age bands are 0–1, 2–3, 4–5 and 6+ years. Mileage bands are below 10,000, 10,000–below 30,000, 30,000–below 60,000 and 60,000+ miles. Battery-wear proxy is mileage divided by 10,000, representing cumulative use exposure only. The data contain no measured battery state of health, charging history or battery replacement history. This proxy cannot establish battery degradation, and is a linear rescaling of an existing predictor. Its added predictive benefit may therefore be zero. The old mileage-below-100 flag is preserved as very_low_mileage_flag.

All new features use fixed row-level rules and do not use prices, target statistics or full-sample quantiles. M5 should compare the baseline with the baseline plus these features on identical development-set CV folds, using the same model and tuning budget. Imputation and encoding must be fitted inside each training fold. Selection should use CV only; evaluate the held-out test after selection. Report log-scale MAE and dollar-scale MAE/RMSE/R² with units clearly distinguished. Predictive benefit has not yet been tested by M1. Hand-built scores are candidates, not validated vehicle inspections.
